## 一、整体背景与初始目标

### 1.1 项目定位

Agents Memory Tools 是一个跨智能体会话记忆工作台：

- 后端：纯 Python `ThreadingHTTPServer`，单端口 **18922**，同时托管前端静态产物与 REST API；
- 前端：Next.js 15 + React 19 + Tailwind + SWR + Zustand，`output: 'export'` 静态导出到 `frontend/out`；
- 解析引擎：`session-migrate 0.11.0`（安装在项目 `.venv`），负责读取 Claude Code、Antigravity、WorkBuddy、Trae、Cursor、Copilot 等平台的会话库；
- 索引：SQLite FTS5（`dialogue_fts.sqlite3`）全文检索 + 快照缓存 + 稳定 ETag + gzip/304；
- 服务层：`services/`（detail / snapshot / turns / fields 等），**单向依赖：services 不得 import web_app.py**。

### 1.2 本次任务的初始目标

1. 接手两个 Antigravity 会话数据库（`C:\Users\HP\.gemini\antigravity\conversations\35cd8f87-….db`、`c9243851-….db`）中记录的项目上下文，还原既有功能与开发进度；

3. 之后追加 UI 主题 / SVG 图标美化（**该部分后续全部作废，未落地**）。

## 三、各需求对应的改动与交付物

### N1–N2：Antigravity 会话详情恢复

**问题根因**

- 旧版会话库 `trajectory_meta.trajectory_type = 4`（CLI cascade）；2026-11 之后新版 IDE 写成 `22`；
- `session-migrate 0.11.0` 的严格校验只认 4，直接抛
  `Antigravity database must contain one CLI cascade trajectory (count=0, all=[(..., 22, 22)])`；
- 另一类错误：子代理会话 `trajectory_metadata_blob` 字段 6（root）写的是父会话 id，校验报
  `trajectory metadata root ID is inconsistent`。

**改动（`web_app.py`）**

1. `_install_antigravity_child_session_compat()`：读取路径（`generated=False`）把 root 当作 conversation_id 交给原校验；写入路径不变。
2. `_AntigravityRowsCompat` / `_AntigravityTrajectoryCompat`：只拦截 `FROM trajectory_meta` 查询，把"唯一一条 type=22"归一化为 4；其它 SQL 与连接属性原样透传。
3. `_install_antigravity_trajectory_type_compat()`：先走原校验，捕获特定错误后再用兼容结果集重试；`generated=True`（写入路径）不启用，避免产出不合规迁移包。

> 兼容是**运行时 monkey-patch**，不修改 `.venv` 内 `session_migrate` 源码。升级 session-migrate 后必须重新验证这两个补丁。

**结果**：Antigravity 详情 139/141 恢复；剩余 2 个为源库 `steps=0`（空轨迹，非解析问题）。

### 6.2 关键注意事项（踩坑清单）

1. **单端口**：只允许 18922；3000 端口是旧 Next 开发服务，不要重启它，停止脚本也只杀 18922。
2. **VBS 必须纯 ASCII**：WSH 按 ANSI 解析，中文注释会破坏语法导致无法启动。
3. **改后端必须重启进程**：`web_app.py` 无热重载；前端改动需重新 `npm run build`（或依赖启动脚本自动重建）。
4. **兼容层是 monkey-patch**：不改 `.venv` 内 `session_migrate`；升级依赖后先跑回归，确认 `trajectory_type=22` 与子会话 root 两个补丁仍生效。
5. **`TOKEN_CACHE_VERSION` 是口径开关**：任何 Token 统计逻辑变更都必须 +1，否则旧缓存会让结果看起来"没生效"。
6. **Claude 逐行累计是用户决策**：不要在后续"优化"中改成按 id 去重。
7. **数据源只读**：所有会话库（`.db` / `.jsonl` / `state.vscdb`）只读访问，禁止写入。
8. **提交前复核 diff**：本项目出现过外部进程把工作区整批还原回 HEAD 的情况；`git add` 前先 `git status` + `git diff`。
9. **改后门禁**：四个脚本必须全绿（见 §4.4），否则不得声称完成。
10. **服务层单向依赖**：`services/*` 不得 import `web_app.py`，否则破坏分层与自测。
